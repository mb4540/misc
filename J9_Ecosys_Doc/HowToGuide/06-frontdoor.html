6.1 — Certificates: you need two

CloudFront only accepts a certificate from us-east-1. The ALB only accepts one from its own region. So the same domain gets validated twice, from two provider aliases in the same Terraform layer.

Ecosystem/infra/terraform/60-frontdoor/providers.tf

provider "aws" {
  region              = var.region              # us-west-2
  allowed_account_ids = ["824999955649"]
}

# CloudFront and its WAF are global services whose control plane lives here.
provider "aws" {
  alias               = "useast1"
  region              = "us-east-1"
  allowed_account_ids = ["824999955649"]
}

Ecosystem/infra/terraform/60-frontdoor/acm.tf

# Only create certificates when a domain is actually configured. With
# domain_name = "" (the dev default), CloudFront serves on its own
# *.cloudfront.net hostname with the AWS-managed certificate and none of this
# runs. That is a fully working system — see 6.5.
locals {
  use_domain = var.domain_name != ""
  # prod: jemba9.com  ·  dev with a domain: dev.jemba9.com
  fqdn = local.is_prod ? var.domain_name : "dev.${var.domain_name}"
}

resource "aws_acm_certificate" "cloudfront" {
  count             = local.use_domain ? 1 : 0
  provider          = aws.useast1
  domain_name       = local.fqdn
  validation_method = "DNS"

  lifecycle { create_before_destroy = true }
}

resource "aws_acm_certificate" "alb" {
  count             = local.use_domain ? 1 : 0
  domain_name       = local.fqdn
  validation_method = "DNS"

  lifecycle { create_before_destroy = true }
}

# Both certificates validate against the same DNS records, so if the hosted zone
# is reachable this is automatic. If it is not — see 6.5 — you will need to hand
# the validation records to whoever controls the zone and wait.
resource "aws_route53_record" "validation" {
  for_each = local.use_domain && var.hosted_zone_id != "" ? {
    for dvo in aws_acm_certificate.cloudfront[0].domain_validation_options :
    dvo.domain_name => {
      name   = dvo.resource_record_name
      record = dvo.resource_record_value
      type   = dvo.resource_record_type
    }
  } : {}

  zone_id         = var.hosted_zone_id
  name            = each.value.name
  type            = each.value.type
  records         = [each.value.record]
  ttl             = 60
  allow_overwrite = true
}

6.2 — WAF

Three managed rule groups and one rate limit. Deliberately modest: the application already does progressive lockout on login and rate-limits event ingest to 300 per minute per app, so the WAF is an outer coarse net, not the primary control.

Ecosystem/infra/terraform/60-frontdoor/waf.tf

resource "aws_wafv2_web_acl" "main" {
  provider = aws.useast1          # CLOUDFRONT scope must live in us-east-1
  count    = var.enable_waf ? 1 : 0

  name  = "${local.prefix}-waf"
  scope = "CLOUDFRONT"

  default_action { allow {} }

  # 1 — the AWS common set. Start in COUNT mode for a week, read the logs, then
  # switch to block. Going straight to block on a Next.js app tends to break
  # server-action POSTs and large form bodies.
  rule {
    name     = "common"
    priority = 10
    override_action { count {} }        # change to `none {}` once you have watched it
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesCommonRuleSet"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "common"
      sampled_requests_enabled   = true
    }
  }

  rule {
    name     = "bad-inputs"
    priority = 20
    override_action { none {} }
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesKnownBadInputsRuleSet"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "bad-inputs"
      sampled_requests_enabled   = true
    }
  }

  rule {
    name     = "sqli"
    priority = 30
    override_action { none {} }
    statement {
      managed_rule_group_statement {
        vendor_name = "AWS"
        name        = "AWSManagedRulesSQLiRuleSet"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "sqli"
      sampled_requests_enabled   = true
    }
  }

  # 2 — a broad rate limit. 2000 requests per 5 minutes per IP is generous for a
  # human and cheap insurance against a crawler.
  rule {
    name     = "rate-limit"
    priority = 100
    action { block {} }
    statement {
      rate_based_statement {
        limit              = 2000
        aggregate_key_type = "IP"
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "rate-limit"
      sampled_requests_enabled   = true
    }
  }

  # 3 — a tighter limit on the auth surface specifically.
  rule {
    name     = "rate-limit-auth"
    priority = 110
    action { block {} }
    statement {
      rate_based_statement {
        limit              = 200
        aggregate_key_type = "IP"
        scope_down_statement {
          byte_match_statement {
            positional_constraint = "STARTS_WITH"
            search_string         = "/api/auth"
            field_to_match { uri_path {} }
            text_transformation {
              priority = 0
              type     = "LOWERCASE"
            }
          }
        }
      }
    }
    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "rate-limit-auth"
      sampled_requests_enabled   = true
    }
  }

  visibility_config {
    cloudwatch_metrics_enabled = true
    metric_name                = "${local.prefix}-waf"
    sampled_requests_enabled   = true
  }
}
Do not block the common rule set on day one

AWSManagedRulesCommonRuleSet includes SizeRestrictions_BODY and several cross-site-scripting body rules that fire on legitimate Next.js server-action payloads and on the Data Room's Excel export requests. Run it in count mode, look at the sampled requests after a week of real use, add targeted rule exclusions, and then switch to none (which means "do not override; block as the rule group intends").

If you block from the start you will spend your first week debugging 403s that look like application bugs.

6.3 — CloudFront

One distribution per environment, one origin (the public ALB), and ordered cache behaviors. The behaviors exist to differentiate caching, not to route — routing is the ALB's job, as set up in chapter 5.

Ecosystem/infra/terraform/60-frontdoor/cloudfront.tf

# The shared secret that proves a request reached the ALB through CloudFront.
resource "random_password" "origin_verify" {
  length  = 48
  special = false
}

resource "aws_ssm_parameter" "origin_verify" {
  name   = "/j9/${local.env}/frontdoor/ORIGIN_VERIFY_SECRET"
  type   = "SecureString"
  key_id = data.terraform_remote_state.secrets.outputs.kms_key_arn
  value  = random_password.origin_verify.result
}

# ------------------------------------------------------------------- policies
# Dynamic app traffic: cache nothing, forward everything the app needs.
resource "aws_cloudfront_cache_policy" "none" {
  name        = "${local.prefix}-no-cache"
  default_ttl = 0
  min_ttl     = 0
  max_ttl     = 0

  parameters_in_cache_key_and_forwarded_to_origin {
    enable_accept_encoding_brotli = true
    enable_accept_encoding_gzip   = true
    cookies_config  { cookie_behavior = "none" }
    headers_config  { header_behavior = "none" }
    query_strings_config { query_string_behavior = "none" }
  }
}

resource "aws_cloudfront_origin_request_policy" "all" {
  name = "${local.prefix}-forward-all"
  cookies_config       { cookie_behavior       = "all" }
  query_strings_config { query_string_behavior = "all" }
  headers_config {
    header_behavior = "allViewerAndWhitelistCloudFront"
    headers { items = ["CloudFront-Viewer-Address"] }
  }
}

# Hashed static assets: cache hard, forward nothing.
resource "aws_cloudfront_cache_policy" "static" {
  name        = "${local.prefix}-static"
  default_ttl = 31536000
  min_ttl     = 31536000
  max_ttl     = 31536000

  parameters_in_cache_key_and_forwarded_to_origin {
    enable_accept_encoding_brotli = true
    enable_accept_encoding_gzip   = true
    cookies_config  { cookie_behavior = "none" }
    headers_config  { header_behavior = "none" }
    query_strings_config { query_string_behavior = "none" }
  }
}

# ------------------------------------------------------------- distribution
resource "aws_cloudfront_distribution" "main" {
  enabled         = true
  is_ipv6_enabled = true
  comment         = "Jemba9 ecosystem front door — ${local.env}"
  price_class     = local.is_prod ? "PriceClass_100" : "PriceClass_100"
  http_version    = "http2and3"
  web_acl_id      = var.enable_waf ? aws_wafv2_web_acl.main[0].arn : null

  aliases = local.use_domain ? [local.fqdn] : []

  origin {
    origin_id   = "alb"
    domain_name = data.terraform_remote_state.compute.outputs.public_alb_dns_name

    custom_origin_config {
      origin_protocol_policy = "https-only"
      http_port              = 80
      https_port             = 443
      origin_ssl_protocols   = ["TLSv1.2"]
      origin_read_timeout    = 60
      origin_keepalive_timeout = 30
    }

    # The other half of the ALB listener-rule condition from chapter 5.
    custom_header {
      name  = "X-Origin-Verify"
      value = random_password.origin_verify.result
    }
  }

  # ---- default: everything dynamic goes to the platform, uncached
  default_cache_behavior {
    target_origin_id       = "alb"
    viewer_protocol_policy = "redirect-to-https"
    allowed_methods        = ["GET", "HEAD", "OPTIONS", "PUT", "POST", "PATCH", "DELETE"]
    cached_methods         = ["GET", "HEAD"]
    compress               = true

    cache_policy_id          = aws_cloudfront_cache_policy.none.id
    origin_request_policy_id = aws_cloudfront_origin_request_policy.all.id
  }

  # ---- hashed build assets, cached for a year
  # Next.js content-hashes these filenames, so a stale cache is impossible.
  ordered_cache_behavior {
    path_pattern           = "/_next/static/*"
    target_origin_id       = "alb"
    viewer_protocol_policy = "redirect-to-https"
    allowed_methods        = ["GET", "HEAD"]
    cached_methods         = ["GET", "HEAD"]
    compress               = true
    cache_policy_id        = aws_cloudfront_cache_policy.static.id
  }

  # Each app serves its own assets under its base path.
  ordered_cache_behavior {
    path_pattern           = "/okr/_next/static/*"
    target_origin_id       = "alb"
    viewer_protocol_policy = "redirect-to-https"
    allowed_methods        = ["GET", "HEAD"]
    cached_methods         = ["GET", "HEAD"]
    compress               = true
    cache_policy_id        = aws_cloudfront_cache_policy.static.id
  }

  ordered_cache_behavior {
    path_pattern           = "/dataroom/_next/static/*"
    target_origin_id       = "alb"
    viewer_protocol_policy = "redirect-to-https"
    allowed_methods        = ["GET", "HEAD"]
    cached_methods         = ["GET", "HEAD"]
    compress               = true
    cache_policy_id        = aws_cloudfront_cache_policy.static.id
  }

  # ---- health endpoints: never cached, so the poller sees the truth
  ordered_cache_behavior {
    path_pattern           = "*healthz"
    target_origin_id       = "alb"
    viewer_protocol_policy = "https-only"
    allowed_methods        = ["GET", "HEAD"]
    cached_methods         = ["GET", "HEAD"]
    compress               = false
    cache_policy_id        = aws_cloudfront_cache_policy.none.id
  }

  viewer_certificate {
    cloudfront_default_certificate = local.use_domain ? false : true
    acm_certificate_arn            = local.use_domain ? aws_acm_certificate.cloudfront[0].arn : null
    ssl_support_method             = local.use_domain ? "sni-only" : null
    minimum_protocol_version       = local.use_domain ? "TLSv1.2_2021" : null
  }

  restrictions {
    geo_restriction { restriction_type = "none" }
  }

  logging_config {
    bucket          = aws_s3_bucket.cf_logs.bucket_domain_name
    prefix          = "cloudfront/"
    include_cookies = false
  }

  # Do NOT add a custom_error_response for 5xx. A broken app origin should return
  # its own error on its own path; a distribution-wide error page would hide which
  # unit of the building is down.
}
Why no caching at all on dynamic paths

Every dynamic response in this system is either a server-rendered page that depends on the viewer's session and their effective permissions, or an API response that does. Caching any of it risks serving one user's authorized view to another — the exact failure the whole authorization design exists to prevent.

The performance you would gain is available more safely inside the application, through Next's own data cache and the platform's session-baked permission fast path. Leave the CDN as a TLS terminator, a compressor, and a static-asset cache.

6.4 — What the origin-verify secret does and does not do

The ALB is internet-facing, so its DNS name resolves publicly. Two things stop a direct request:

  1. The security group only admits the CloudFront origin-facing prefix list. That is the real control.
  2. The listener rules require the X-Origin-Verify header. That is defence in depth, and it also catches the case where someone widens the security group for debugging and forgets to narrow it again.

Rotating it is a two-step, zero-downtime operation, and you should do it once deliberately so you know it works:

# 1. Add the new value to the listener rules alongside the old (the http_header
#    condition accepts a list of values), apply.
# 2. Change the CloudFront custom_header to the new value, apply, wait for the
#    distribution to finish deploying.
# 3. Remove the old value from the listener rules, apply.

aws cloudfront get-distribution --id E1XXXXXXXXXX \
  --query 'Distribution.Status'      # must read "Deployed" before step 3
CloudFront VPC origins are the better long-term answer

Everything above exists because CloudFront historically could not reach a private ALB. CloudFront now supports VPC origins, which let the distribution talk to an internal ALB directly — no public ALB, no prefix list, no shared header, nothing publicly resolvable at all.

It is the cleaner architecture and worth adopting. It is not the pattern documented here because the prefix-list-plus-header approach works on every provider version and is what the repo's own docs/deployment/aws.md describes ("ECS Fargate services behind an internal ALB"). Check the current provider support for aws_cloudfront_vpc_origin and, if it is available to you, prefer it — and then delete this section from your copy of the guide.

6.5 — DNS: the one genuine blocker

From Ecosystem/docs/deployment/dns.md, and it is still true:

jemba9.com's authoritative DNS is a Route 53 hosted zone in a different AWS account, and the current live IP is Amazon-owned and outside this account. The entire platform can be built, deployed, and operated now at a CloudFront *.cloudfront.net URL; attaching the real hostname is the last mile.

That document was written when the target account was the wrong one. The situation needs re-confirming against account 824999955649, and there are exactly two questions to answer:

QuestionIf yesIf no
Is the jemba9.com hosted zone in 824999955649? Nothing is blocked. Set hosted_zone_id in tfvars and the ALIAS records below apply automatically. Go to the next question.
Can you get an ALIAS record added to whichever account holds the zone? One record per environment, pointing at the CloudFront distribution. No migration, no downtime. Re-delegate: get registrar access, create a new hosted zone in 824999955649, copy the existing records into it, then repoint the domain's name servers. Plan for a propagation window and do it out of hours.
# Find out where the zone actually lives.
aws route53 list-hosted-zones-by-name --dns-name jemba9.com --profile j9
# Empty result means the zone is not in 824999955649.

# What the world currently thinks:
dig +short NS jemba9.com
dig +short A  jemba9.com
whois jemba9.com | grep -iE 'registrar|name server'

Operating without the domain

Everything works. What you must do is make the CloudFront hostname the canonical URL in three places, exactly as dns.md prescribes:

  1. PLATFORM_SELF_URL in the platform and worker task definitions.
  2. The Cognito app client's callback_urls and logout_urls — which is why the identity layer gets applied a second time after the front door exists.
  3. company.portal_url in company.config.yaml, plus NEXT_PUBLIC_PLATFORM_PORTAL_URL for the Data Room's signed-out redirect.
# The ordering, concretely, on a first build:
cd 60-frontdoor && terraform apply -var-file=../shared/dev.tfvars
CF=$(terraform output -raw distribution_domain_name)    # dxxxxxxxxxxxxx.cloudfront.net

cd ../30-identity
terraform apply -var-file=../shared/dev.tfvars -var "front_door_url=https://$CF"

cd ../50-compute
terraform apply -var-file=../shared/dev.tfvars -var "front_door_url=https://$CF"
# The task definitions change, so this rolls the platform and worker services.
Front-door smoke test 
CF=dxxxxxxxxxxxxx.cloudfront.net

curl -si "https://$CF/healthz" | head -20
# Expect: 200, and these headers from next.config.ts —
#   strict-transport-security: max-age=63072000; includeSubDomains; preload
#   content-security-policy: default-src 'self'; ...
#   x-frame-options: DENY
#   x-content-type-options: nosniff

curl -si "https://$CF/okr/healthz"       | head -5
curl -si "https://$CF/dataroom/healthz"  | head -5

# HTTP must redirect, not serve:
curl -sI "http://$CF/" | head -3         # expect 301 to https

# A cached asset should report a hit on the second request:
curl -sI "https://$CF/_next/static/chunks/main.js" | grep -i x-cache

If HSTS is missing, you are not reaching the app — you are seeing a CloudFront or ALB error page. If x-cache never says Hit from cloudfront on a static asset, your static behavior's path pattern does not match what Next is actually emitting; check the real asset URL in the browser's network tab.
