Schematic Copilot

An agentic AI assistant for aerospace PCB schematic development — overview, proposed architecture, and interactive concept mockup.

The problem

Aerospace schematic capture leans on two tightly coupled but separately maintained artifacts — the schematic itself and the datasheets of every part in it. Today, tying the two together is a manual, memory-dependent process, and manual cross-checking is where work items get missed.

Schematic

The logical circuit diagram — components, pins, and nets — created in schematic-capture tools (Altium, Cadence OrCAD/Allegro, KiCad). It expresses design intent: power flow, signal paths, protection circuitry, before any physical layout exists.

Datasheet

The manufacturer's reference for a specific part — pinout, absolute maximum ratings, recommended operating conditions, timing/switching characteristics, and application notes (required decoupling caps, pull-ups, termination, layout guidance).

Where they meet in the development process

1

Part Research & Selection

Datasheets compared against requirements and qualification level (temp range, MIL-SPEC, rad-hardened variants).

2

Schematic Capture & Simulation

Each symbol wired per the datasheet's recommended application circuit — correct pinout, bypass caps, pull-ups, termination.

3

Board Layout

Datasheet layout guidance (trace length, proximity, thermal pads) carried into placement and routing.

4

Verification & Validation

Design-rule and electrical checks confirm the schematic doesn't violate any component's datasheet limits.

Why work items get missed

Every one of those handoffs today depends on an engineer remembering to re-open a datasheet PDF, re-check a value, and manually log a follow-up. On a board with hundreds of parts, that's hundreds of manual cross-checks with no forcing function — nothing stops a missing decoupling cap or an unterminated net from silently surviving to review.

Qualification & traceability

In aerospace specifically, formal design reviews expect documented traceability from each schematic net/component choice back to its datasheet specification and the system requirement it satisfies:

StandardRelevance
DO-254Design assurance for airborne electronic hardware — requires traceable, reviewable design evidence.
AS9100Aerospace quality management — process discipline and objective evidence for every design decision.
IPC-2221 / MIL-STDDocumentation, manufacturing, and testing standards referenced during schematic/layout review.

The proposed direction

An agentic assistant, not another manual checklist

Rather than a static checklist an engineer has to remember to run, an AI agent watches the schematic as it's built, cross-references each component against its datasheet automatically, and surfaces flagged work items in a live queue — so nothing depends on an engineer remembering a manual step. See the Architecture and Interactive Mockup tabs for the proposed shape of this.

Proposed simple architecture

A thin web front end, a stateless API layer, an LLM-based agent orchestrator, and a Databricks Lakebase Postgres database for transactional state — sitting alongside the existing Databricks lakehouse used for SAG data.

Why Lakebase for this

Low-latency OLTP

Lakebase is a fully managed Postgres database purpose-built for transactional, low-latency reads/writes — a fit for a live work-item queue that engineers refresh constantly, unlike a SQL warehouse tuned for analytics.

Native Unity Catalog integration

Sits on the same Databricks platform already in use for SAG, so schematic/work-item tables can sync with lakehouse data without a separate ETL pipeline to stand up.

Built as an agent state store

Databricks positions Lakebase explicitly as a state store for AI agents — a direct match for an orchestrator that needs to persist findings, decisions, and conversation state per schematic.
