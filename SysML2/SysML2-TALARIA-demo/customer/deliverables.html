Why these do not drift 1

// A deliverable is a view definition over the model.
view def DeratingAnalysisReport {
    import J9Avionics::tiaPowerBoard::**;
    import J9Avionics::requirements::**;

    render asDocument;

    @CustomerVisibility {
        maturityLevel      = "L3";
        releasedToCustomer = true;
        exportMarking      = "None";
    }
}

// Rendered against a tag, so the PDF and the model agree by
// construction — the document cannot describe a board that
// has since been edited.
The failure mode this removes. A report generated in March describes the board as it was in March. If the BOM changes in April, today there is nothing linking the stale PDF to the change — you find out at the review. As a view over a tagged baseline, the document declares which snapshot it renders, and the platform can tell you it is behind the current model and what specifically moved.

1
view / viewpoint — documents as renderings
A deliverable is a declared view over the model, rendered at a named commit. It cannot silently disagree with the design, because it is derived from it rather than assembled alongside it.
Today: deliverable stores an S3 URI, a format, a version and an approval. The document is generated once and then becomes an independent artefact that ages.
2
The model itself as a deliverable
Alongside the PDF, the customer can take the model. For a customer with their own MBSE estate this is the difference between receiving a report about a board and receiving the board.
Today: deliverables leave as PDF or DOCX. Nothing downstream can compute over them.
3
metadata def — maturity and export marking
Visibility gating is domain vocabulary attached to model elements through KerML metadata rather than application-layer permission checks. The gate travels with the element through export and API read, so a scoped external reader gets the same answer the portal does.
Today: maturity gating is real and works, implemented in the deliverable status field and the portal's access logic. It is enforced at the application boundary, so it does not survive the artefact leaving.
