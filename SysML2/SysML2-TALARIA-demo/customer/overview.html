Tag on a Commit — the customer view is pinned
Customer-facing state cites a named baseline rather than showing whatever the database contains right now. That matters most in the awkward case: a customer quotes a number from a screen three weeks ago and asks why it changed. With a tag, the old number is still retrievable and the difference is a diff.
Today: the customer portal reads live rows. It is accurate at page load and unreproducible afterwards, because there is no snapshot to go back to.
2
Verification status the customer can trust
"4 of 6 verified" is the result of evaluating each requirement's constraint over the parts it binds to, at the pinned commit. It is not a status somebody remembered to update before the review call.
Today: requirement status is a curated field. The customer is trusting the process rather than the computation.
3
Mission profile as bound parameters
TID, RDM and thermal range are inputs to the constraints. If the customer changes the orbit, the platform knows exactly which verifications are invalidated rather than requiring a full re-analysis to find out.
Today: mission_profile is a real table and is passed into each run, but the dependency between a profile change and the affected results is not modelled.
