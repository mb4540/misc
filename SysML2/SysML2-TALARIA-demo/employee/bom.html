SysML 2.0 ON THIS SCREEN

Click any purple marker above to jump here
1
part def and part usage — 69 definitions, 142 usages
A part def is the catalogue entry for a component type; a part usage is that type appearing at a specific place on the board with its own values. The BOM line and the reference designator stop being one row with a string of designators, and become one definition with many addressable instances nested under board → assembly → part.
Today: the part table stores refDes as a single varchar and the analyst expands "C52–C55" at run time. A finding therefore names a group, not a component.
2
Typed quantities from the ISQ / SI libraries
50 [V] is a quantity value, not a number with an implied unit. A rule written in volts cannot silently consume millivolts, and a krad/rad mix-up in a radiation margin becomes a parse error rather than a wrong answer that looks right.
Today: ratedVoltage is a doublePrecision column whose unit lives in the column name. Better than a string, but nothing enforces it.
3
port def and connect — the connectivity layer
Ports are declared interaction points; connect joins them. This is what lets an applied stress have a provenance: 48 V on C24 is derived from the rail it sits on, not asserted. It is also the hook that makes real ECAD netlist import meaningful rather than a spreadsheet in disguise.
Today: there is no net, node or port table anywhere in the schema. actualVoltage is an unsourced number, and the ECAD integration is stubbed.
4
metadata def — waivers travel with the part
A waiver attaches to the element it excuses. D7 stays visibly non-compliant and visibly waived, with the justification in the model rather than in a table you have to remember to join.
Today: waiver is a separate table keyed on finding_id. The information is all there; it just does not travel with the export.
5
Textual notation as an export format
The whole model serialises to text with a published grammar. It diffs in a pull request, opens in any conformant tool, and can be generated or checked by an agent. This is the cheapest of the integration options — a serialiser over the existing Drizzle schema, no schema change required.
Today: a project leaves TALARIA as a PDF or a DOCX. Nothing downstream can compute over it.
