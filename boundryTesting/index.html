The Gap You Suspected Is Real

Project/program-level boundary testing is not covered — and it's worse than simply "untested." It surfaced a known, documented, unfixed bug that sits underneath your question.

  1. POST /api/chat/stream (the actual RAPDA answer endpoint) takes activeProjectId straight from the client request body and passes it into buildProjectContext(activeProjectId), which queries the database by project_id alone — with zero ownership check of any kind: not tenant-level, not project-level. backend/src/routes/chat.ts (lines 69–76)  →  backend/src/lib/rapda-context.ts (lines 6–21)
  2. This is explicitly excluded from the isolation matrix (route-inventory.ts line 124: "SSE + external AI Gateway LLM; not harness-testable… buildProjectContext(activeProjectId) has no tenant check") and documented as Follow-Up Item #8 in the P0-04 execution plan — flagged in the runbook as "the highest-priority open item from this suite's build-out." It has never been fixed, and there is no automated test proving it, cross-tenant or same-tenant. documents/plans/done/18-tenant-isolation-test-suite-execution.md  ·  app/roadmap/src/pages/runbooks/rb02-tenant-isolation-testing.ts §5
  3. More fundamental to your specific question: the app has no project-level access-control model at all. extractTenantId / requireTenantAccess / assertProjectTenant only ever check tenant_id; there is no user-to-project membership table. Any customer authenticated to Tenant A can already list and read every project belonging to Tenant A (GET /api/projects filters by tenant_id only). "RAPDA should not answer for a different project in the same tenant" is not currently a stated product requirement anywhere in the docs — it's a gap in both the test suite and the underlying authorization model. backend/src/middleware/tenant.ts  ·  backend/src/lib/tenant-ownership.ts
Green = proven by the P0-04 isolation suite. Red / dashed = open gap: RAPDA's chat context has no ownership check at all, so it is exposed both across tenants and across sibling projects within the same tenant.
