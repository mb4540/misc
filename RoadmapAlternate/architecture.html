Auth & Identity Model

Authentication is handled by backend/src/middleware/auth.ts:

  • Extracts JWT from Authorization: Bearer header or accessToken cookie
  • Verifies against Cognito JWKS endpoint (cached)
  • Resolves user role from database using Cognito sub
  • Attaches req.user and req.tenantId for downstream handlers

Tenant isolation is enforced by backend/src/middleware/tenant.ts — every query must pass tenantId from req.tenantId. Any route that skips this in its WHERE clause is a data leak; that claim is now provable via the integration test matrix — see P0-04.

OpenTelemetry Implementation Plan

  1. Install SDK — @opentelemetry/sdk-node, auto-instrumentations, OTLP trace exporter.
  2. Instrument entry point — backend/src/tracing.ts loaded before server.ts; export to AWS X-Ray via OTLP.
  3. LangGraph node instrumentation — wrap each node in a manual span with agent_type, tenant_id, run_id, token counts.
  4. Trace–log correlation — inject traceId/spanId into every structured log record.

Agent Workflow Monitoring — Design

  • Run-level span: one parent span per pipeline run, labeled run_id/tenant_id/agent_type.
  • HITL wait time: alert if > 24h between request and human action.
  • Tool call success rate: tracked separately from LLM errors.
  • Token budget alarm: warn if a single run exceeds a configurable token ceiling.
  • Stale run detection: runs stuck in running past a timeout are flagged and paged.
Audit trail gap: agent trace persistence covers agent outputs but not who approved a HITL step, who uploaded a BOM version, who changed a project status, or admin actions. Needs an audit_events table — also a SOC 2 Availability control evidence artifact.

Cost Management

  • AWS Budget alarm configured in infra/lib/monitoring-stack.ts — good baseline.
  • Databricks model serving costs are not tracked per-tenant — P1-09.
  • No cost anomaly detection beyond the static budget alarm.
  • S3 lifecycle policies not confirmed — large BOM uploads could accumulate.
