03 — COMMERCIAL & OPS READINESS

Commercial & Operational Readiness

Launch gates, go-to-market narrative, and the operational tooling/process needed before paying customers. LBGUPS scorecard lives on Overview; item status lives on Backlog.
Bottom line: the platform is demo-ready today for sophisticated technical audiences. It is not yet beta-ready for paying customers. The gap is operational (no support channel, no status page, no metering) and product/legal (billing, contracts) — not core product capability. Both prior security gaps (secrets posture, tenant boundary test coverage) are remediated.

Commercial Gates

Gate 1 — Investor / Partner Demo

Verdict: Ready with prep

The core platform — agentic pipeline execution, HITL approval, BOM parsing, compliance report generation — is demonstrable end-to-end today. A well-prepared demo with curated data and a stable dev environment can convincingly show the product's differentiated value.

What to show: project creation → agent pipeline → node-by-node trace · HITL approval step (pause, review, approve, resume) · BOM ingestion + compliance check · agent trace timeline · multi-tenant architecture (two tenants, no cross-access) · CDK estate + CloudWatch dashboard for technical credibility.

Demo risks: LLM latency (prepare a pre-seeded fallback run) · no staging means a dev deploy gone wrong could break the demo (freeze deploys 48h before) · avoid raw env-var dumps on screen.

Gate 2 — Private Beta (First Paying Customer)

Verdict: Not yet ready

All Phase 0 backlog items must close, plus a status page and support ticket channel — see the live status on Backlog → Phase 0, P1-04, and P1-08.

Waivable for a sophisticated design partner: full self-service provisioning (P1-01, can be operator-assisted) · Stripe billing (P1-10, can invoice manually) · onboarding docs (P1-13, can be walkthrough-assisted).

Value Proposition & Recommended Narrative

For aerospace & defense suppliers

"Jemba9 — Space Assurance Gateway eliminates the manual compliance overhead that slows your engineering teams. Our AI agent pipelines run your qualification, BOM compliance, and assurance workflows end-to-end — with human-in-the-loop review at every critical decision — and produce audit-ready documentation your customers accept. You get faster cycle times, fewer NCRs, and a complete digital trail from requirement to delivery."

Credibility Risks to Address

  • "Is my data safe with an AI system?" → Tenant isolation architecture brief; data never used to train models; Databricks model serving privacy policy.
  • "What happens when the AI is wrong?" → HITL approval gates are the answer; show the approval step in the demo.
  • "Are you a real company with real support?" → Needs: status page, support SLA, named account contact.
  • "Do you have AS9100 customers?" → Phase 1: get one referenceable design partner from the aerospace supply chain.

Internal Admin Console — Requirements

Internal-only tool (not customer-facing) so operations can manage the platform without raw DB access.

Tenant Management
  • List tenants with status (active, trial, suspended, churned)
  • Create tenant + Cognito group in one action, send invite
  • Suspend/reactivate (blocks API access)
  • View per-tenant config (plan, limits, model overrides)
Usage & Billing View
  • Per-tenant tokens, agent runs, BOM uploads — this period vs last
  • Cost estimate (Databricks serving cost × tokens)
  • Flagged tenants: approaching limit, anomalous spend
Run Health
  • Active runs: agent type, tenant, started, current node, status
  • Failed runs: error type, stack trace, run ID (link to trace)
  • Stale runs: running past timeout
  • HITL pending: approver, elapsed wait time
Access Control
  • Accessible only to system_admin role
  • All actions written to audit_events
  • No direct DB mutation — typed API endpoints only

Runbooks Required (Phase 0 / Phase 1)

  1. ECS task OOM / container crash — identify, force redeploy, check memory headroom.
  2. Databricks Postgres connection failure — connectivity check, pool reset, failover steps.
  3. LLM endpoint timeout / model serving down — check Databricks status, switch fallback model, communicate.
  4. Stale / hung agent run — identify, cancel, clean up a run stuck in running.
  5. Database point-in-time restore — step-by-step restore to staging, verify, promote if needed. (P0-06)
  6. Tenant data access emergency (suspected leak) — isolate tenant, revoke tokens, preserve evidence, notify.
  7. CDK deploy rollback — roll back a failed ECS deploy or CDK stack update.

Release Management

  • Release notes published to the status page changelog on every production deployment.
  • Semantic versioning — breaking API changes require a MAJOR bump and 30-day deprecation notice.
  • No Friday afternoon production deployments (unless emergency hotfix).
  • All deployments require staging validation first (enforced by CI gate once P0-03 lands).
