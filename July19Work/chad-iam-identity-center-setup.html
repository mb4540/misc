2. Attach the existing deny policy to sag-developers-staging

A customer-managed IAM policy already exists in the jemba9-dev account (824999955649) — created by our CDK CodeCommitGovernanceStack, but deliberately left unattached until this step: 

Policy name: sag-developer-main-protection-staging
Policy ARN:  arn:aws:iam::824999955649:policy/sag-developer-main-protection-staging

Denies:
  - codecommit:GitPush on refs/heads/main
  - codecommit:OverridePullRequestApprovalRules
  1. Still in IAM Identity Center → left nav → Permission sets → Create permission set.
  2. Choose Custom permission set. Name it SagDeveloperStaging.
  3. Under Policies for this permission set, click Add a customer managed policy (this attaches by name/path — it works because the policy already exists in the target account from step 3 below). Enter the policy name exactly: sag-developer-main-protection-staging.
  4. You'll likely also want to add an AWS-managed baseline policy (e.g. PowerUserAccess or a narrower one your team already uses) alongside the deny policy, so developers have normal working access minus the two denied actions above. Deny statements always win regardless of what else is attached.
  5. Save the permission set.

6. Create the CodeCommit approval-rule template

No CDK/CloudFormation resource exists for this (confirmed during Phase 5) — it's CLI-only. Convert the role's IAM role ARN from step 5 into its assumed-role ARN pattern (swap :role/ for :assumed-role/, drop the aws-reserved/sso.amazonaws.com/<region>/ prefix if present, and append /* as a wildcard session name):

export AWS_PROFILE=jemba9-dev
export AWS_REGION=us-east-2

aws codecommit create-approval-rule-template \
  --approval-rule-template-name "sag-main-2-approvals" \
  --approval-rule-template-content '{
    "Version": "2018-11-08",
    "DestinationReferences": ["refs/heads/main"],
    "Statements": [{
      "Type": "Approvers",
      "NumberOfApprovalsNeeded": 2,
      "ApprovalPoolMembers": [
        "arn:aws:sts::824999955649:assumed-role/AWSReservedSSO_<PermissionSetName>_<hash>/*"
      ]
    }]
  }' \
  --region us-east-2

Replace AWSReservedSSO_<PermissionSetName>_<hash> with the exact role name segment found in step 5.

7. Associate the template with the repository 
aws codecommit associate-approval-rule-template-with-repository \
  --approval-rule-template-name "sag-main-2-approvals" \
  --repository-name j9ccgit \
  --region us-east-2
